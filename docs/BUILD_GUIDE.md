# MortgageForge build guide

Everything you need to run, extend, grow and monetize MortgageForge. The site is plain HTML, CSS and JavaScript with no build step and no backend. GitHub Pages serves this repository as it is.

---

## 1. Tech stack (and why)

| Layer | Choice | Why |
|---|---|---|
| Pages | Static HTML, one file per tool, generated by `scripts/build-pages.mjs` | Every tool has its own crawlable URL, title, meta and FAQ schema. No framework or bundler to maintain. |
| Logic | Vanilla ES modules (`assets/js/`) | Loads natively in every modern browser. The finance engine is pure functions with Node tests. |
| Charts | Chart.js 4.4.7, vendored in `assets/vendor/` | Small, accessible tooltips, no CDN calls (better privacy and no third-party outages). |
| PDF reading | pdf.js 4.10.38, vendored, loaded only on the statement page | Files are read inside the tab; nothing is uploaded. |
| Font | Public Sans (variable, self-hosted, SIL OFL) | Designed for US government forms, which suits a tool built around Loan Estimates and statements. No Google Fonts request. |
| Storage | `localStorage` (inputs, theme, saved scenarios), share links encode state in the URL hash | No accounts, no database, nothing to secure. |
| Hosting | GitHub Pages (free) | HTTPS, CDN, custom domain support. Cloudflare Pages or Netlify work the same way. |
| Tests | `node --test` (built into Node 18+) | `npm test` checks payments, amortization, PMI/MIP/VA rules, refinance, affordability, ARM and the optimizer. |

### Core user flows

**Buyer:** Payment calculator → adjust price/down/rate (sliders) → read "Ways to pay less" → Apply a lever → Compare loan types → "Use this loan" → Save scenario.

**Owner:** Read a statement (drop PDF) → confirm numbers → "Use these numbers" (switches every tool to *My current loan*) → PMI removal (earliest route, extra needed) → Extra payments (pick a strategy, "Use") → Amortization (see payoff and milestones) → Refinance (true break-even).

**Shopper with two offers:** Enter offer A → Save → enter offer B → Save → Saved scenarios compares them side by side and highlights the best value on each row.

All tools share one state object, so numbers carry over automatically ("one-click transfer"). Navigation swaps the tool in place without reloading the page, while every tool still has its own real URL for search engines.

## 5. Statement upload

`assets/js/statement.js`:

1. `pdfText(file)` lazy-loads the vendored pdf.js only when someone drops a file, reads up to 6 pages, and rebuilds text lines from item positions.
2. `parseStatement(text)` runs label-anchored patterns (unpaid principal balance, interest rate, principal and interest, escrow, mortgage insurance, amount due, due date, maturity date, original amount). Each match carries a confidence level shown as "found" or "check this".
3. Remaining payments come from maturity date minus next due date, or are solved from balance, rate and payment.
4. The user reviews and edits every value before **Use these numbers** writes them into *My current loan*.

Fallbacks: password-protected PDF → clear message; scanned PDF or photo → image preview beside the form for manual entry; any format → paste statement text into the textarea and the same parser runs.

To support a specific servicer's wording, add a pattern to `RULES` in `statement.js`. Optional future step: OCR for photos with tesseract.js loaded on demand (about 2 MB plus language data), still fully local.

## 7. Monetization without hurting the tools

All switches live in `assets/js/site-config.js` and are **off** by default.

- **Display ads**: placeholders `<div class="slot" data-slot="results">` (under results) and `data-slot="article"` (inside the article) exist on every page and stay invisible until enabled. Ads load after the page is idle and never inside the inputs panel or the ribbon. Apply for AdSense once the guides are live and you have some traffic; add your `client` and slot IDs, set `enabled: true`. Add a consent banner (Google's CMP is free) before enabling ads for EU/UK visitors, and update the privacy page.
- **Affiliates**: add entries to `affiliates` with the tools they belong to (e.g. refinance-rate marketplace on `refinance`, homeowners-insurance quotes on `payment`, credit monitoring on `afford`). They render as a labeled "Next steps · partner links" block under results with `rel="sponsored"`. Only add programs you're approved for.
- **Light freemium (later)**: keep every calculator free. Candidates for paid: branded PDF plan export, unlimited synced scenarios, an ad-free toggle, embeddable widgets for agents and loan officers.
- **Email capture (optional)**: a "Email me my plan" form via a free form service (Formspree, Buttondown free tier). Keep it optional and below results.

## 8. Koinos tip jar (optional)

The built-in tip jar is deliberately simple and has no blockchain dependency: set `tipJar.enabled = true` and `tipJar.koinAddress` in `site-config.js`. The footer shows a "Tip in KOIN" button that copies your address and links to it on a block explorer. Nothing loads unless it's enabled.

A wallet-connected version is a reasonable next step, but I couldn't confirm the current state of the Koinos network or its JavaScript libraries, so verify the following against the official Koinos docs before building it:

- **Wallet connection**: Koinos browser wallets (historically Kondor) expose a signer to web pages. Load the wallet's provider only after the user clicks "Tip", never on page load.
- **Library**: `koilib` (MIT) builds and signs transactions in the browser. Vendor a pinned version into `assets/vendor/` the same way as Chart.js.
- **Feeless for users**: Koinos uses mana (regenerating resource credits tied to KOIN balance) instead of gas. A tip sender spends their own mana; for features where *you* want to pay, such as an on-chain "share scenario" record, you can set your own account as the transaction payer so users need no KOIN. That requires a small signing service you control, which breaks "no backend", so keep it out of the core path.
- **Sketch** (adjust to the current koilib API):

```js
// assets/js/tip.js — loaded only when the user clicks "Tip"
const { Contract, utils } = await import('../vendor/koilib.min.js');
const signer = await window.kondor?.getSigner?.();            // wallet-provided signer
const koin = new Contract({ id: KOIN_CONTRACT_ID, abi: utils.tokenAbi, signer, provider: signer.provider });
const { transaction } = await koin.functions.transfer({ from: signer.getAddress(), to: SITE.tipJar.koinAddress, value: utils.parseUnits('5', 8) });
await transaction.wait();
```

Keep all calculators fully usable with zero blockchain interaction.

## 9. Deploy to GitHub Pages

1. Push this repository to `main` (already done if you're reading this on GitHub).
2. On GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, branch `main`, folder `/ (root)`, **Save**.
3. Wait about a minute, then open `https://bawcejawn.github.io/LoanCalc/`.
4. Check: the payment updates as you drag sliders, the ribbon shows your numbers, the PMI page timeline renders, and the statement page reads a PDF.
5. **Search Console**: add the URL-prefix property `https://bawcejawn.github.io/LoanCalc/`, verify with the HTML-tag method (add the meta tag to the template in `build-pages.mjs`, run `npm run pages`, push), then submit `sitemap.xml`.
6. **Bing Webmaster Tools**: import from Search Console.
7. **Custom domain (optional, about $10/year)**: add a `CNAME` file containing the domain, point DNS at GitHub Pages, tick **Enforce HTTPS**, and change `BASE` in `scripts/build-pages.mjs` (plus the `/LoanCalc/` paths in its 404 section), then `npm run pages`.
8. Each January: update `assets/js/config.js` with the new FHFA conforming limit and any HUD/VA/USDA changes, update `UPDATED` in `build-pages.mjs`, run `npm test` and `npm run pages`, push.

Local preview: any static server pointed at the parent folder works, e.g. `npx serve ..` then open `/LoanCalc/`. Opening `index.html` straight from disk won't work because browsers block ES modules on `file://`.

## 10. Progressive disclosure (how the site stays simple)

The site starts with one question and reveals more as the visitor shows interest. State lives in `localStorage` under `mf:ux` (`assets/js/ux.js`); nothing is sent anywhere.

1. **Home is a guided start** (`tools/start.js`): "What would you like to do?" → 4 goals → 3–6 questions, one per screen with big inputs, quick-pick chips, Back/Skip. Owners can jump to uploading a statement instead.
2. **Summary page after the questions**: the monthly payment, the 3 best moves (from the savings engine), and "Your tools" for their goal. One or two "You might also want" cards are dashed to look optional.
3. **Personal navigation**: the sidebar shows Home, then only "Your tools" (goal tools + anything opened). Everything else sits under a collapsed "All tools".
4. **Each tool shows two result panels first**. The rest wait behind one "Show N more" button that names what's inside. The choice is remembered per tool.
5. **Inputs show the essentials**. Loan type, taxes, insurance, HOA, escrow and original loan details are under "More options".
6. **A "Where to next" card** at the end of each tool suggests 2 related tools (`RELATED` map in `ux.js`), preferring ones not opened yet. Opening one adds it to "Your tools".
7. **On phones** the answer comes first and the inputs follow under "Change the numbers"; the sticky bar keeps the key figures in view.

To tune: edit `GOALS` (which tools each goal starts with), `RELATED` (what to suggest next), `STEPS` in `start.js` (the questions), and `keep` in `progressive()` in `app.js` (how many panels show before "Show more").

## 11. Soft credit pulls: why not on this site, and what to do instead

A real soft pull isn't something a static, free, privacy-first site can do safely:

- **Legal basis**: under the FCRA even a soft pull needs a permissible purpose, typically the consumer's written instructions for prequalification, with disclosures and an audit trail. (Not legal advice; talk to counsel before going near this.)
- **Bureau access**: you'd need a credentialed account with a bureau or reseller, which involves an application, verification of your business and use case, security requirements, and per-pull fees.
- **A backend**: API keys and credit data can't live in browser code, so you'd need a server. The data you'd then hold (SSN, credit report) brings safeguarding duties under the GLBA Safeguards Rule, breach exposure, and more compliance if you use it to pre-qualify or sell leads.

What MortgageForge does instead (built):

- **Self-reported score band** everywhere a score matters, with a note that we never check credit.
- **Credit score impact tool** (`/credit-score-mortgage-rate-calculator/`): rate, PMI and payment at every band, estimated from Fannie Mae's LLPA matrix (updated 09-30-2026) relative to the rate the user was quoted. It shows the dollar value of moving up one band and links to the free official reports at AnnualCreditReport.com.
- **Partner path for real pre-qualification (later)**: add an affiliate link to a licensed lender or rate marketplace that does the soft pull on *their* site with their consent flow. You earn the referral; the data never touches yours. Put it in `SITE.affiliates` with `tools: ['credit', 'savings']`.

## 12. Document readers

`assets/js/statement.js` reads three document types locally with pdf.js and detects which one it is:

| Document | Fields | Used for |
|---|---|---|
| Mortgage statement | balance, rate, P&I, escrow, MI, maturity → payments left, original amount, next due | Current-loan mode, PMI, refi, escrow check |
| Homeowners insurance declarations page | premium, all-perils and wind/hail deductibles, Coverage A–E, renewal date | Deductible savings and claim-free break-even, renewal reminder (.ics), dwelling coverage check, escrow check |
| Loan Estimate / Closing Disclosure | sale price, loan amount, rate, term, P&I, escrow, closing costs, cash to close, points | Fills the purchase plan; tests whether the points pay off within the stay horizon |

After confirming, visitors land on **My savings** (`/mortgage-savings-check/`), which splits results into "Save without paying more" (PMI, refinance with a rate target, credit, insurance, escrow, rate shopping, points) and "Put extra money to work" (best extra-payment strategy, payoff-by-date goal, the free 1/12 "biweekly"), with a chart, equity at 5/10/15 years, and print.

Deeper calculators added to existing tools:
- **Extra payments**: payoff-by-date solver, true biweekly vs 1/12-extra (with fee input), lump sum recast vs keep payment, cost of waiting.
- **Refinance**: the highest rate that still pays within your stay (and within 3 years), points vs no points table, year-by-year advantage.
- **PMI**: handles "already at 80%", downloadable HPA cancellation request letter, calendar reminder for the 80% date.
